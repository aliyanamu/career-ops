The legacy TSV → `merge-tracker.mjs` flow still exists for batch workers but writes into the generated file.

## Evaluation Flow (Single Offer)

1. **Input**: User pastes JD text or URL
2. **Extract**: Playwright/WebFetch extracts JD from URL
3. **Classify**: Detect archetype (1 of 6 types)
4. **Evaluate**: 6 blocks (A-F):
   - A: Role summary
   - B: CV match (gaps + mitigation)
   - C: Level strategy
   - D: Comp research (WebSearch)
   - E: CV personalization plan
   - F: Interview prep (STAR stories)
5. **Score**: Weighted average across 10 dimensions (1-5)
6. **Report**: Save as `reports/{num}-{company}-{date}.md`
7. **PDF**: Generate ATS-optimized CV (`scripts/generate-pdf.mjs`)
8. **Track**: Write TSV to `batch/tracker-additions/`, auto-merged

## Batch Processing

The batch system processes multiple offers in parallel:

```
batch-input.tsv    →  batch-runner.sh  →  N × headless CLI workers
(id, url, source)     (orchestrator)       (self-contained prompt)
                           │
                    batch-state.tsv
                    (tracks progress)
```

Each worker is a headless AI CLI instance — the bundled `batch-runner.sh` invokes `claude -p`, but the architecture supports any CLI's headless mode (see the Headless / Batch Mode table in `AGENTS.md` for the correct command per CLI). Workers produce:
- Report .md
- PDF
- Tracker TSV line

The orchestrator manages parallelism, state, retries, and resume.

## Data Flow

```
cv.md                    →  Evaluation context
article-digest.md        →  Proof points for matching
config/profile.yml       →  Candidate identity
portals.yml              →  Scanner configuration
templates/states.yml     →  Canonical status values
templates/cv-template.html → PDF generation template
```

## File Naming Conventions

- Reports: `{###}-{company-slug}-{YYYY-MM-DD}.md` (3-digit zero-padded)
- PDFs: `cv-candidate-{company-slug}-{YYYY-MM-DD}.pdf`
- Tracker TSVs: `batch/tracker-additions/{id}.tsv`

## Pipeline Integrity

Scripts maintain data consistency:

| Script | Purpose |
|--------|---------|
| `scripts/gen-applications-md.mjs` | Regenerates `applications.md` from `jobs.json` (source of truth) |
| `scripts/merge-tracker.mjs` | Merges batch TSV additions (legacy batch flow) |
| `scripts/verify-pipeline.mjs` | Health check: statuses, duplicates, links |
| `scripts/dedup-tracker.mjs` | Removes duplicate entries by company+role |
| `scripts/normalize-statuses.mjs` | Maps status aliases to canonical values |
| `scripts/cv-sync-check.mjs` | Validates setup consistency |

## Web Tracker

The `tracker/` directory contains a React app (Vite) that visualizes the pipeline, reading `data/jobs.json` directly:

- Filter tabs and multiple sort modes
- Grouped/flat view
- Inline status changes

`npm run build` (in `tracker/`) outputs the static site to `tracker/dist/` (gitignored). CI (`.github/workflows/build-tracker.yml`) builds and deploys it to GitHub Pages via Actions.
